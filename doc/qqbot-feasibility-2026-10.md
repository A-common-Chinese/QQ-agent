# QQ 官方机器人通道 · 可行性调研（2026-10-24）

> 依据：QQ 机器人官方文档（bot.q.qq.com/wiki），页面更新日期分别为
> 消息收发概述 2026-07-21、群消息（全量模式）2026-10-21、变更记录 2026-10-21、FAQ 2026-10-21、运营规范 2023-11-09。
> 本文只写"文档明确写了"的内容；推断处标注「推断」。

## 一、结论

**可以做，而且比预期好**：官方通道现在支持

- **群内全量消息接收**（群主授权后，非 @ 的消息也能收到）
- **主动推送**（群主授权后，1000 条/群/日）
- 群管理（禁言/移除/黑名单/入群审批，2026-08/09 新增）
- Markdown + 按钮（全部机器人可用，无需申请）

所以"群友型人格 + 自由接话"在**自建群 + 群主授权**的前提下可以基本实现，不必降级成"只应答 @"。
代价是：个人主体**不能公开使用**（只能加自己是群主/管理员的群），且要遵守平台内容规范。

## 二、能力与配额（文档原文整理）

### 收发场景

| 场景 | 发消息 | 收事件 |
|---|---|---|
| 单聊 | `POST /v2/users/{user_openid}/messages` | `C2C_MESSAGE_CREATE` |
| 群聊 | `POST /v2/groups/{group_openid}/messages` | `GROUP_AT_MESSAGE_CREATE`（仅 @）/ **`GROUP_MESSAGE_CREATE`（全量）** |
| 频道 | 子频道/私信接口 | 频道消息事件 |

### 被动 / 主动消息

| 类型 | 有效期 | 每条消息可回复次数 |
|---|---|---|
| 被动（单聊） | 60 分钟 | 4 次 |
| 被动（群聊） | 5 分钟 | 5 次 |

主动消息（需要群主在手机 QQ 里给机器人开「主动推送消息」权限）：

| 场景 | Bot 维度频控 | 单关系维度频控 | 每日上限 |
|---|---|---|---|
| 单聊 | 10 qps | 20 qpm | 1000 条/用户 |
| 群聊 | 60 qpm | 20 qpm | **1000 条/群** |

- 互动召回：`is_wakeup=true`，用户对话后 30 天内 4 个周期各 1 条
- 用户在客户端可关闭"允许主动发送"，关闭后主动消息必失败

### 消息类型

| msg_type | 类型 | 发送 | 接收 |
|---|---|---|---|
| 0 | 文本 | ✅ | ✅ |
| 2 | Markdown | ✅ | - |
| 7 | 富媒体（需先上传拿 `file_info`） | ✅ | ✅ |

- 富媒体要走分片上传（推荐）或整文件上传；`file_info` 有 `ttl`；单聊/群聊上传接口不互通
- 2026-10-21 新增「素材管理」：图片传平台得 `qqbot-media://` 引用，可在 Markdown 里用
- 撤回：自己发的消息 **2 分钟内**可撤回
- 去重：同 `msg_id` 可能重复推送，用 `msg_seq` 去重；被动回复同 `msg_id+msg_seq` 会失败，需递增

### 主体与准入（关键限制）

| 项 | 个人主体 | 企业主体 |
|---|---|---|
| 机器人数量 | 5 个 | 10 个（同主体合计 50） |
| 公开使用（被任意人添加） | ❌ **不支持** | ✅ 已开放 |
| 能加哪些群 | 仅**自己是群主/管理员**的群 | 公开使用后可被任意群添加 |
| 私聊测试 | 管理端「开发设置」加开发体验用户号码 | 同左 |
| 主体认证 | 需实名（含 QQ 钱包实名） | 需工商认证 |

**群主在手机 QQ 添加机器人时可设置三项权限**：

1. 接收全量消息（→ 才能收到 `GROUP_MESSAGE_CREATE`）
2. 主动推送消息（→ 才不受"仅被动回复"限制）
3. 撤回成员消息（需把机器人设为群管理员）

### 群管理接口（2026-08/09 新增）

- 群成员：列表 / 信息 / 批量移除 / 黑名单查询与操作
- 禁言：查询禁言状态 / 设置禁言
- 入群：申请列表 / 审批 / 自动审批策略
- 域名统一为 `api.bot.qq.com`（2026-08-10）

## 三、和我们现有能力的差距

| 现在（OneBot/SnowLuma） | 官方通道 | 影响 |
|---|---|---|
| 全量群消息 | ✅ 群主授权后可全量 | 关键项，已具备 |
| 主动发言 | ✅ 1000 条/群/日（需授权） | 够用 |
| 拍一拍 | ❌ 无对应接口（文档未见；第三方 litepoke 是 NapCat 插件） | 需降级：禁用 send_poke 工具与相关提示词 |
| 表情回应/贴表情 | ❌ 文档只见"消息按钮/键盘" | 降级 |
| 引用回复 | ⚠️ 接收侧有 `msg_elements`(103 引用)；发送侧是否支持引用参数**待实测** | 可能影响"指代不清时引用" |
| 富媒体 | ✅ 但需上传 + ttl + 单聊群聊不互通 | 需要 media 上传适配层 |
| 群名片/头像/资料 | ❌ 无接口 | 降级（人格里"改群名片"类行为去掉） |
| 消息编辑/流式 | ✅ 支持流式消息（单聊） | 可选增强 |
| 身份可见性 | 官方是"机器人"身份，昵称/头像固定 | **人设"装真人"效果打折**（客户端会显示机器人标识） |

> 「推断」：官方机器人客户端自带机器人标识与资料页，无法像 OneBot 那样伪装成普通群友；
> 但"群友语气"仍可通过文案实现，只是用户点开资料页就知道是机器人。

## 四、合规要点（必须先确认）

1. **AI 生成内容标识**：《人工智能生成合成内容标识办法》已施行，平台侧可能要求显式标识；
   官方 FAQ 也写明"AI 功能由开发者自主选配……违规使用会导致机器人或相关账号封禁"
2. **内容安全**：运营规范建议接入内容安全检测接口；群聊场景建议过滤敏感内容
3. **不得隐藏/掩饰用户真实身份**（运营规范 5.14(3)）——针对用户身份，不是 bot，但"人格化伪装"仍有审核风险
4. **数据规范**：收集用户数据需告知与同意；终止服务后 24h 内删除
5. 平台保留"要求修改/下架/封禁"的权力，机器人封禁**不支持解封**

## 五、工程方案（双通道）

```
                 ┌─ onebot adapter（现有，行为不变）
src/transport ←──┤
                 └─ qqbot adapter（官方：AppID/Secret → AccessToken → WS 网关 + HTTP API）
        ↓ 统一内部事件/动作
orchestrator / prompt / tools / sender / 记忆 / 人格卡  ← 不动
```

### 抽象接口（P1）

- 事件：`message`（含 chatKey、发送者、内容、mentions、引用、附件）、`notice`（入群/退群/被禁言…）
- 动作：`send(chatKey, parts)`、`recall(chatKey, msgId)`、`memberInfo`、`mute`、`kick`、`uploadMedia`
- 能力声明：`capabilities = { readAllMessages, canProactive, canPoke, canRecallOthers, canMute, markdown, media }`
- 所有"人格/工具"按 capabilities 开关：官方通道自动关闭 poke、群名片、主动插话提示词等

### 阶段与工作量

| 阶段 | 内容 | 估计 |
|---|---|---|
| P1 | 抽 `src/transport/`，OneBot 实现搬过去，行为零变化 | 1–2 天 |
| P2 | qqbot adapter：鉴权/WS 网关（hello/heartbeat/resume/seq）、消息去重（msg_id+msg_seq）、被动回复窗口、media 上传、markdown 兜底文本 | 3–5 天 |
| P3 | capabilities 降级层：工具可见性、提示词分支、状态面板 | 1 天 |
| P4 | 控制台「接入方式」页：AppID/Secret、环境（沙箱/正式）、权限自检、通道状态 | 0.5–1 天 |

### 需要实测的项（文档没写死）

1. 发送接口是否支持引用某条消息（`msg_id` 参数）
2. 全量模式下被动回复窗口是否仍是 5 分钟/5 次（按条计还是按群计）
3. 机器人能否被设为群管理员并撤回他人消息（群主授权链路）
4. 个人主体在**自建群**里的全量模式是否稳定（是否有人数/消息量限制）
5. Markdown 在群聊的实际渲染效果与长度上限

## 六、建议

1. **官方通道做默认**（合规、稳定），定位"自建群的可授权 AI 群友"
2. **SnowLuma 保留为高级模式**（玩法完整、但封号风险），启动时明示风险，不与官方通道同时接管同一群
3. 先做 P1（纯重构，零风险），再做 P2 沙箱联调；`dsh-agent` 与 DSH 桥不受影响
4. 对外发布时把"个人主体只能加自己的群"写清楚，避免用户注册后发现加不了别人的群
